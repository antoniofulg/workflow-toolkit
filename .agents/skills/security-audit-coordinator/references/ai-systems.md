# AI, retrieval, memory and tool surfaces

- Trace untrusted retrieved documents, web content, messages and uploaded files into
  system/developer/user instruction assembly. Preserve provenance and privilege;
  suspicious prose alone is not proof of an unauthorized outcome.
- Check cross-session/tenant context isolation, persistent memory writes, retrieval
  filters, deletion and stale authorization. A stored summary or embedding is a
  derived data copy with its own readers and lifecycle.
- Bind tool/provider identity, arguments, destinations, disclosure and side effects
  to current delegated authority. Metadata, schemas, annotations and model plans are
  untrusted inputs, not policy. Recheck approval after identity or arguments change.
- Compare tool schema validation with downstream dispatch and sink interpretation.
  Bound iterations, retries, recursive delegation, context/output size and paid work.
- For subagents and MCP, map inherited credentials, filesystem/network authority,
  token recipient/scope and consumer/provider authorization separately. Transport
  labels or model instructions do not enforce these boundaries.
- Treat generated HTML, Markdown, code, URLs and logs as untrusted output at the
  rendering or execution boundary. Confirm a real sink and affected principal.

Use controlled traces or dummy data. Never execute hostile instructions, disclose
private context or contact attacker-controlled destinations merely to test a lead.
